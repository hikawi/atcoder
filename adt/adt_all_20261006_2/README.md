## C - Christmas Trees

無限に続いている線にて、座標$A$から双方向に$M$マスごとに木を植える（$A$も含む）。座標$L$と$R$の中にはいくつの木が立っているの求めよ（$L$と$R$座標の木も含む）。これは最初簡単だと思いましたが、自分の計算仕方は時々ただ１ずれていますから、ACはできませんでした。

```python
inside = (r - l - 1) // m
left = (l % m) == (a % m)
right = (r % m) == (a % m)

print(inside + left if l == r else inside + left + right)
```

こうなら、

```plaintext
   0 2
..#..#..#..#
    ^ ^
    L R

A = 0
M = 2
L = 1
R = 3
```

この場合には間違ってしまいます。コードのように計算してみると

$$
\lfloor \frac{R-L-1}{M} \rfloor = \lfloor \frac{3-1-1}{2} \rfloor = 0
$$

でも、確かに中には一個があったではありませんか。なので、正解なのは、両方$A$引いて計算すべきです。それで$0$から$R-A$までいくつの木が立っているのかと、$0$から$L-A-1$引けば結果となるという理解です。

## F - Cookies and Greedy Takahashi

1D線にクッキ$N$個があります。$A_i$とはクッキの座標で、$A_i$は相異なる。$0$から、高橋さんはもっとも近くにあるクッキの座標に移って拾う。それで、同じく全部拾うまで繰り返す。二つのクッキが同じ距離であったら、座標の小さいほうに向かう。全部拾ったら移動距離を求めよ。

この問題はもちろん全探検したら、百パーセントTLEですね。最初に考えているのは、どうやってある配列から最小値を得て、それで全部を更新してソートする方法ですが、どうやら遅すぎそうです。それで、追加または取りぬくことを最適化できるデータ構成があるかなと考えましたが、普通にありますけど、一つ取ったあとには全部更新しなければならないので（高橋の座標が変更したし、どの要素が最小値だと判断するのはその要素自体と現在の座標によっているし）、無理だとおもいます。最後、グラフで表して、ゼロのノードから最速のパスを求める問題として扱うつもりでしたけど、一つの気づきました。

想像してみれば、どうせ左か右か、二つの方向しかないという行動にみえます。どうせ１D線だし、グラフではなく、連結リストの方に似ています。そう考えて、全部の要素を取って、ソートしてから、双方向連結リストを作りました。でも、スタートから始めず、ゼロのノードから（リストの中）移り始めました。この方法ではACできました。
